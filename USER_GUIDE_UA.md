# Короткий посібник користувача

## Перегляд стану

Відкрийте `dashboard.html` у корені проєкту. Dashboard показує 10 розділів і читає дані, які були збережені під час останнього оновлення. Зовнішня копія зручно збережена поруч із проєктом у `outputs/ncdr-dashboard.html`. Щоб синхронізувати обидві копії з SQLite після запуску задач, виконайте:

```powershell
python src/agent/build_dashboard.py
```

## Продовження черги

З кореня цього проєкту виконайте:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File src/agent/run_coordinator.ps1 -MaxTasks 4
```

Запуск виконує не більше 4 придатних задач за раз, зберігає результати в SQLite та продовжується наступним запуском. Ollama запускається приховано лише якщо його API недоступний; wrapper зупиняє лише процес, який сам створив. Жодне завдання автозапуску Windows не створюється.

## Важливі шляхи

- `inventory/discs_manifest.csv` і `.json`: шляхи, розміри, часи модифікації та SHA-256 усіх джерел.
- `project_state.sqlite`: контрольні точки задач, evidence, етапні ворота й модельні результати.
- `TASK_BACKLOG.sqlite`: сумісне представлення черги.
- `EVIDENCE_LEDGER.sqlite`: інвентаризовані файли, hash і класифікація.
- `reports/model_benchmark.json`: повні 18-задачні виходи моделей, оцінки й ресурси.
- `reports/COMPATIBILITY_MATRIX.md` та `reports/FORMAT_UNKNOWN.md`: межі доведеного й відкриті питання.

Докази першого запуску не змінюють і не копіюють вихідні файли. Будь-яка майбутня зміна має відбуватися тільки в робочій копії, а не в `Desktop\crz\NCDR`.
