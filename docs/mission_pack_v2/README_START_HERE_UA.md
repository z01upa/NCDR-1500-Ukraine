# NCDR Autonomous Lab 2.0 - одноразовий пакет переходу на результат

Створено 26.10.2026. Пакет містить **46** конкретних робочих елементів з критеріями приймання, архітектуру постійного керування, системні промпти локальних моделей, контракт подій і тестовий сценарій. Це **специфікація та backlog**, не вже встановлена програма.

## Як використати

1. Зберегти копію поточного робочого проєкту Windows та SQLite checkpoint, не змінювати оригінали Desktop\crz\NCDR.
2. Відкрити той самий робочий проєкт у Codex на Lenovo та прикріпити цей ZIP або розпаковану папку.
3. Передати Codex **один раз** файл `CODEX_ONE_TIME_IMPLEMENTATION_ORDER_UA.md` як головне завдання. Якщо пакет не прикріплено автоматично, покласти його в робочий репозиторій.
4. Codex зобов'язаний об'єднати пакет із реальним кодом і станом SQLite, не створюючи другий менеджер паралельно.
5. Після доведення E2E продовження запускається незалежним Windows Worker за збереженим планом. Codex викликається програмно лише за потреби.

## Що не робити

- Не перезапускати монолітний OSM conversion без збереження наявних shard/checkpoint.
- Не скидати усі `BLOCKED` у `PENDING` без виправлення причини.
- Не дозволяти AI змінювати вихідні диски або самостійно помічати незрозумілі байти як доведені.
- Не вважати **564 DONE** або **35% з GUI** доказом готовності NCDR-диска.
- Virtual CID і редактор POI GUI виведені з поточних цілей. POI як **тип даних на диску** залишається необхідним.

## Файли

- `CODEX_ONE_TIME_IMPLEMENTATION_ORDER_UA.md` - одноразовий наказ на впровадження.
- `ARCHITECTURE_AND_RECOVERY.md` - архітектура, state machine, anti-deadlock, автозапуск.
- `plans/task_backlog.json` - 46 машинозчитувані задачі з реальними output/acceptance.
- `plans/goal_gates.json` - об'єктивні ворота між етапами, без штучного %.
- `schemas/task.schema.json` - мінімальний валідатор файлів задач.
- `schemas/capability_request.schema.json` - запит на виправлення/розширення Codex.
- `prompts/LOCAL_DIRECTOR_UA.md`, `LOCAL_SUPERVISOR_UA.md`, `CODEX_ENGINEER_UA.md` - ролі.
- `policies/model_and_resources.json` - запуск однієї великої моделі та безпечні обмеження.
- `tests/ACCEPTANCE_TEST_PLAN.md` - реальні сценарії приймання.
- `reports/REPORT_REQUIREMENTS.md` - звіти й індикатори.
- `KNOWN_STATE_AND_INVARIANTS.md` - вхідний відомий стан та джерела доказів.
