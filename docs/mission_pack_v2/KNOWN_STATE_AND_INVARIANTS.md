# Стан, на якому базується міграція

## Доведене з наданих матеріалів (не свіжий live-аудит)

- 26.10.2026 GUI показував DONE=564, BLOCKED=8, CANCELLED=1, PENDING=0. Worker PID 26728, але немає активної задачі. Це **живий процес**, не корисний процес дослідження.
- `AUTO_OSM_NATIONAL_CONVERSION_01` у щоденному звіті було заблоковано після 3600 секунд, а у пізнішому GUI зазначено `ParseError: out of memory`. Це два спостереження, а не доведена одна причина.
- Оперативна пам'ять у GUI ~11.7/31.5 GiB, VRAM ~843/8151 MiB. OOM може бути пов'язаний зі способом парсингу або лімітом конкретного процесу; не робити висновок із загального RAM.
- Звіти підтверджують окремі no-op/field-limited MP0 readback перевірки. **Не доведено** повне розуміння MP0/road graph, writer усієї карти або сумісність фізичного диска.
- Аудит F0 повідомляв 5600 файлів і три дискові набори CD_7185, CD_7186, CD_7190. Старий архів `NCDR_MAP_RESEARCH.zip` містив частковий читач заголовка MP0 і початковий coordinator. Нова версія проєкту знаходиться **на Lenovo**, і її треба інспектувати повторно, не приписуючи їй структуру старого ZIP.
- За старими результатами `*Z.MP0`: marker `(*$SIEMENS&^)`, ASCII поля на offsets 0x10, 0x20, dataset code на 0x30 - підтверджено тільки як частину заголовка. Формат після заголовка ще не доведений.
- DB_0 є окремим артефактом і його висновки не можна переносити на NCDx без доказів.
- Наявні LOCAL Qwen3.5:9b, Qwen3.5:4b та інші Ollama моделі, включно з Qwythos за попередніми повідомленнями. Актуальні встановлені теги перевірити на Windows через `ollama list`.

## Незмінні вимоги

1. **Original media READ_ONLY**, SHA256 перед і після контрольованих експериментів.
2. Згенерований код недовірений: sandbox + whitelist + тести, тільки потім merge.
3. PASS на статистичну перевірку або no-op writer не дорівнює семантичному декодеру дороги чи фізично сумісному диску.
4. Усі нетривіальні факти містять source path + hash + offset/record ID + незалежний repro.
5. Система не займається Virtual CID GUI та окремим редактором POI до нового наказу. Підготовка POI/маршрутизації в дискових даних обов'язкова.
6. HARDWARE_UNVERIFIED залишається, поки не надано модель/ревізію приладу і фізичне приймання.
