# Приймальні тести автономної лабораторії

## Автоматизація і запуск

1. Старт із `PENDING=0`, незалежний G1/G3 ще не готовий. Очікується planner tick -> новий перевірюваний task -> виклик локального Ollama -> реальний артефакт -> test -> next task **без повідомлення користувача**.
2. Kill Worker посеред запису shard та restart. Неповний tmp не зараховано, вже завершені тайли не оброблені повторно, task owner lease recovery доведено.
3. Закрити GUI. Worker продовжує і збільшує verified evidence. Відкрити GUI знову, відображаються актуальні задачі.
4. Перевірити автозапуск після виходу/входу в Windows. Реальне reboot - окремий тест, якщо виконаний. Статус не може стати PASS за сам факт налаштування.
5. Розірвати Ollama з'єднання. Немає втрати даних; fallback/WAITING_MODEL; потім автоматично продовжує.
6. Штучно виправний `KeyError IL`, OOM або invalid script викликає `CAPABILITY_REQUEST` чи конкретний patch workflow, не псує original media і не повторює безкінечно.
7. Codex CLI навмисно недоступний. Director -> local Worker -> незалежний Verifier -> наступна корисна NCDx/OSM задача завершується без Codex; rate-limit окремо фіксується у WAITING_CODEX_QUOTA без повторних викликів.
8. Другий Worker процес не може одночасно захопити ту саму задачу.

## Продуктові етапи

9. NCDx оригінали: цілісність MP0, щонайменше два незалежні readers, строгі boundary checks. Результат «header verified» не автоматично доводить road geometry.
10. Нова структура дороги: витягнуті координати та road graph зі справжніх NCDx і незалежна перевірка на кількох реальних контрольних ділянках.
11. Мінімальна NCDx зміна: no-op byte-perfect та окрема контрольована семантична модифікація на копії, independent reader підтверджує зміни, оригінали незмінні.
12. OSM: обробка тестової території з реальних даних, міжрегіональні зв'язки, односторонні дороги й turn restrictions; витрати пам'яті процесу записані.
13. Національний OSM: resumed process після штучного OOM/time budget, all tiles verified, не втрачено nodes/ways refs, сформовано source manifest + snapshot date.
14. Мінімальний OSM -> NCDx -> незалежний reader: реальний кодований дорожній сегмент із контрольованим зіставленням вихідних координат.
15. Повний образ: незалежний verifier приймає файлову структуру, з дотриманням підтвердженої секторної геометрії. Якщо невідомо - WAITING_EXTERNAL, не PASS.
16. Фізичний тест: з'ясована точна модель та ревізія Opel, образ записаний за перевіреною схемою, реально читається, адресний пошук/маршрут Україною перевірені. Тільки тут status READY.

## Заборони на фальшиве PASS

- SHA-256 збігається -> підтверджена тільки незмінність джерела.
- Статистика байтів -> структура ще не декодована.
- Readback поля MP0 -> готовий writer усієї карти не доведений.
- Локальна OSM симуляція -> CD NCDR сумісність не доведена.
- Windows Task Scheduler enabled -> повна перевірка reboot не доведена.
