# Вибір локальної моделі

Порівняння виконано локально через Ollama на однаковому NCDR benchmark із 18 завдань для кожної з чотирьох установлених моделей, включно з Qwythos 9B v2 Q4_K_M. Кандидатів запускали послідовно, а модель просили вивантажити після запиту. Це один вимірювальний прогін, не гарантія стабільної швидкості.

| Модель | Перевірені відповіді | Час | Корисні відповіді/хв | Peak VRAM |
|---|---:|---:|---:|---:|
| `qwen3.5:4b` | 8 / 18 | 19.686 с | 24.3831 | 4,791 MiB |
| `qwen2.5-coder:7b` | 7 / 18 | 20.571 с | 20.4175 | 5,677 MiB |
| `qwen3.5:9b` | 8 / 18 | 45.865 с | 10.4656 | 7,248 MiB |
| `hf.co/empero-ai/Qwythos-9B-v2-GGUF:Q4_K_M` | 8 / 18 | 45.020 с | 10.6618 | 7,343 MiB |

## Рішення

За виміряною кількістю автоматично перевірених результатів за хвилину координатор обирає `qwen3.5:4b` для коротких гіпотез. `qwen2.5-coder:7b` лишається кандидатом для задач із кодом, а Qwythos — незалежним рецензентом. Benchmarks вимірює відповіді на структурованих запитах, не якість згенерованих програм; перед прийняттям коду обов'язкові окремі обмежений запуск і незалежні тести. Виконується лише одна велика модель за раз на 8 GiB GPU.

Усі моделі дали лише 7–8 правильних/перевірених результатів із 18. Цей результат не допускає writer/зміни для диска. Локальний виконавець уже створив окремий скрипт для порівняння байтів префікса `PDX`; ізольований тест пройдено, детермінована перевірка незалежно підтвердила 8 спільних початкових байтів у трьох регіональних файлах. Це не декодує їхню семантику.

Повні JSON-відповіді, оцінки завдань, metadata моделей і зразки ресурсів: `reports/model_benchmark.json`. Автоматичний вибір максимізує `verified_results_per_minute` серед повністю завершених кандидатів.
