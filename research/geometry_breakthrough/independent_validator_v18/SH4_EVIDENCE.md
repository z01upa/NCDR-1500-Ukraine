# Bounded SH4 evidence
Addresses below are original link VAs; v13 disassembly uses runtime VA = link VA + 0x02000000. Source is the already recovered NavigationRem.dll, not a fresh NK decode. This stage performs static instruction inspection, not full emulation. The earlier v13 bounded p-code replay covers only the reader routines and a field-forwarding prefix.

- 0x0104DBE8 dispatcher: Section4 offset/count at header +0x10/+0x12; call 0x0104D848 at 0x0104DD02. Section5 +0x14/+0x16; call 0x0104D8A0 at 0x0104DD2E. RAM table/count at context +0x2C/+0x30 and +0x34/+0x38. Node stride 10, disk edge stride 14, RAM edge stride 16. Absolute compressed block offsets/sizes and later relative section offsets must reflect growth.
- 0x010688E8 adjacency: 0x0106891A and 0x010689FC use mask 0x0FFF for IDs. 0x01068946..58 rejects a node index >= node count. 0x0106895C..6E handles zero edge count. 0x01068A04..10 checks edge ID < edge count. 0x01068B6E/0x01068BB8 check primary/secondary coordinate bounds. Degree is low nibble and is clamped to 8 in firmware; topology_v6 only has proven physical layouts 1..7 and intentionally rejects unsupported degree8.
- 0x010689BC..0x010689EC selects adjacency start +2 for degree <=4, +4 otherwise. 0x01068AA0..0x01068ACE selects orientation bit j from header upper nibble for degree<=4, byte1 for degree>4. 0x01068AD4..0x01068B26 selects the opposite endpoint and its primary/secondary flag: bit0 means current node=A, bit1 means current node=B. Validator compares that against actual endpoint identities; order changes require corresponding orientation bits.
- Sections7/8/9 dispatch at 0x0104DDDC..0x0104DDE8, 0x0104DE18..26, 0x0104DE56..66. Readers 0x0104DA1C, 0x0104DA98, 0x0104DB44 consume 7/11/13 stored bytes per record, producing 8/12/16 RAM bytes. These accesses prove loaded dependencies, NOT field semantics or which entries must be added. Section6 reader 0x0104D994 consumes length-prefixed records and emits 58-byte RAM slots; semantic/reference validation remains UNKNOWN.
- Edge +4/+5 preserved by 0x0104D8A0 and forwarded by 0x0101FCD8 into cover+0x10/+0x11. Latest transition-rejection-mask proof mentioned by the user is not present on this Mac. Exact bit-to-turn reindexing is therefore not independently certified here.

Evidence source: ../module_recovery_v13/modules/NavigationRem.dll/reachable.jsonl.gz and module.json. Selected instructions are copied into evidence/sh4_selected.json; they remain instruction evidence rather than a complete behavioral model.
