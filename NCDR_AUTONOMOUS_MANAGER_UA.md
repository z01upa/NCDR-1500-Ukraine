# NCDR Autonomous Research Manager

Windows dashboard і фоновий worker інтегровані з наявним `project_state.sqlite`, чергою задач, F0–F9 і доказами NCDR. Qwen3.5 9B постійно виконує роль Director, Qwen2.5-Coder 7B ремонтує вузькі задачі в ізольованій копії, а незалежні тести перевіряють будь-які зміни до promotion. Codex CLI дозволений лише для critical architecture або після збереженої невдачі локального ремонту, з денним бюджетом і одним викликом на request. Rate-limit checkpoint-иться як `WAITING_CODEX_QUOTA` без циклічних спроб; локальні дослідження тривають.

## Встановлення

1. Розпакуйте комплект у корінь наявного `NCDR_MAP_RESEARCH`.
2. Запустіть `windows\install_manager.ps1` у PowerShell від імені поточного користувача. Адміністратор не потрібен.
3. Відкрийте ярлик **NCDR Autonomous Research Manager** у меню Start і натисніть **Запустити дослідження**.

Встановлювач створює обмежену задачу Windows Task Scheduler із запуском при вході користувача й п'ятьма спробами автоматичного перезапуску після помилки. Закриття вікна не зупиняє worker. Якщо черга лишалася в стані `RUNNING` перед перезапуском Windows, worker відновить її зі SQLite checkpoint після наступного входу.

## Керування

- **Запустити дослідження** — зберігає режим RUNNING і запускає окремий worker.
- **Пауза** — дочікується завершення поточної обмеженої задачі, після чого worker не бере нових.
- **Продовжити** — поновлює чергу з останньої контрольної точки.
- **Зупинити** — завершує поточну обмежену задачу й зберігає незавершені задачі.
- **Аварійне зупинення** — завершує дочірній процес і повертає його задачу до SQLite черги.
- **Переглянути результати** — відкриває збережені звіти.

## Межі безпеки

Вихідні диски читаються без запису. Генерований код виконується тільки у власній папці `work\autonomous_manager\sandbox`, в окремому Python-процесі `-I -B`; ремонтна вправа допускає одну точну чисту функцію після перевірки AST. Інші тестові команди вибрані з внутрішнього allowlist і використовують тестові fixtures та SQLite у `work\autonomous_manager\test_tmp`.

Справжній writer для дисків, апаратна сумісність F1 та native NCDx editor не оголошуються готовими. Задача writer зберігає `DISK_NOT_READY`, доки не буде точного пристрою, розібраних записів, byte-preserving roundtrip та незалежної перевірки.

Звіти автономного приймання зберігаються у `reports\autonomy_e2e.json`; робочі журнали й контрольні артефакти — у `work\autonomous_manager` та `project_state.sqlite`.

## Видалення

Запустіть `windows\install_manager.ps1 -Uninstall`. Це прибирає лише автозапуск і ярлик, залишаючи дослідницькі результати й SQLite checkpoint-и на місці.
